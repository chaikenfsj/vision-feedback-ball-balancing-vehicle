## 已修复的问题

1. **目录移动后无法编译。** 原 `build/CMakeCache.txt` 和 Ninja 文件指向 `D:/Project/_worktrees/s1-q6-github-clean`，直接构建报错。已重新生成当前目录的缓存；VS Code 的 Build/Clean 任务现在先执行 Configure。新的 PowerShell 帮助脚本只清理失效的 CMake 元数据，保留 `build/testdeps` 等文件；原 `.cmd` 入口转发至该脚本。另用包含空格的移动目录验证了自动恢复和依赖保留。
2. **Release 的有效性检查失效。** 原 `-Ofast` 编译的 Q6 测试在第 192 行失败：NaN 显式目标被接受。Release/RelWithDebInfo 改用 `-O3`，并显式添加 `-fno-fast-math`；Q5/Q6 测试增加 `-Optimization O3` 参数用于验证优化构建。
3. **OLED 绘图越界。** 点绘制/清除没有坐标检查，`y=64` 可写入相邻列，较大的坐标可超出整个缓冲区。已增加像素边界检查、修正线段边界、限制 ASCII 字体索引，并让字符串在屏幕底部停止，避免换行后越界写入。
4. **OLED 关屏命令错误。** `OLED_DisPlay_Off()` 原发送开屏命令 `0xAF`，已修正为 `0xAE`。
5. **测试依赖不兼容本机 Python。** 原 pyelftools 0.33 需要 Python 3.10，而默认解释器为 3.8.15。固定为已验证的 0.32，并重新安装依赖，包括 Unicorn 在 Python 3.8 下需要的附加依赖。
6. **构建与诊断细节。** CMake preset schema 从 6 改为 3，使其与声明的 CMake 3.22 最低版本一致；编码器诊断改用有长度限制的 `snprintf` 和匹配 `int32_t` 的格式；移除了未使用的按键变量，并按 Q6 开关条件编译 Q2 入口。

未调整控制增益、任务定时、引脚、SysConfig 设置或生成文件。

## 使用方式

在 VS Code 执行默认 Build 任务即可。命令行构建可使用：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .vscode/scripts/ensure-build-directory.ps1 -WorkspaceFolder "$PWD" -CMake "$env:CMAKE_ROOT/bin/cmake.exe"
& "$env:CMAKE_ROOT/bin/cmake.exe" --build --preset build-debug
```
